maxresdefault.jpg is usually 1280×720 when YouTube published it. A 404 is normal—use the next real public still, not a guessed filename.

Quick answer

maxresdefault.jpg is a public thumbnail filename on YouTube’s image CDN. When the file exists it is typically 1280×720. It is not guaranteed for every video. A 404 (or a tiny grey placeholder) means that derivative was never published for that video ID. Paste the watch URL into 11tik and download the first listed size—the tool already skipped missing names and ranked survivors such as hq720, sddefault, or hqdefault.

A missing maxres file is a fallback problem, not proof that the video has no thumbnail.

What is maxresdefault.jpg?

It is a filename, not a magic quality guarantee. The usual JPEG address looks like:

https://i.ytimg.com/vi/VIDEO_ID/maxresdefault.jpg

When YouTube also published a WebP twin, 11tik checks:

https://i.ytimg.com/vi_webp/VIDEO_ID/maxresdefault.webp

Both sit on i.ytimg.com. They are still images—not the video stream, not a Studio private export, and not a 4K master. Pixel expectations and other sizes are covered in the thumbnail size and resolution guide. URL construction is covered in the thumbnail URL guide.

What our 300-video sample showed (not a universal rule)

In our 300-video thumbnail size study, we measured public variant availability for eight filenames per ID. In that sample only, maxresdefault validated for 286 of 300 video IDs (95.33%). The other 14 of 300 had no usable maxres file—but every one of those 14 still returned a valid hqdefault public still. That pattern is sample-scoped evidence for fallback behavior, not a guarantee for every YouTube upload.

When maxres is missing in your own check, treat it as a thumbnail variant problem: step down to the next validated public filename rather than assuming the video has no thumbnail at all. Video-level failures (private, deleted, restricted) are a separate diagnosis—see the thumbnail not appearing guide.

Why can a real YouTube video still return 404 for maxres?

  • Older uploads never received a maxres derivative.
  • The custom thumbnail source was smaller than 1280×720.
  • Studio is still processing a new custom upload.
  • Some Shorts and auto-generated stills stop at mid sizes.
  • The video is restricted and does not expose public stills at all.

A working watch page only proves the video ID is valid. It does not prove every filename under /vi/ exists.

How to recognize an unavailable variant

Open the candidate URL in a new tab. Failures look like:

  • HTTP error / blank response
  • A very small grey or default tile when you expected 1280×720
  • An image that loads but is clearly a placeholder for a missing high-res file

11tik’s browser validator marks candidates invalid when the image fails to load or when a high expected size collapses to a tiny placeholder (about 120×90). Those candidates never appear as “fake HD” cards.

  2. Build candidate URLs from the preset list above.

That is why guessed maxres links disappear from the UI when they fail: the extractor refuses to invent a 1280×720 file.

Practical troubleshooting checklist

  1. Confirm the video is public and the ID is correct.
  2. Test maxresdefault.jpg once. If it fails, stop guessing.
  3. Paste the same link into 11tik.
  4. Download the first listed still, or copy its image URL.
  5. If nothing appears, the video may be private, deleted, age-gated, or without public stills.
  6. For CMS use, prefer a hosted copy of a validated still over a hotlinked CDN path. See the blog / Open Graph guide.

Common mistakes

  • Assuming every video has maxres because one popular video does.
  • Hard-coding maxresdefault.jpg in production HTML without a check.
  • Calling a stretched hqdefault “maxres.”
  • Confusing a player screenshot with the CDN still — screenshot vs real thumbnail.
  • Expecting 4K. Public maxres is typically 1280×720 when present — highest quality guide.

FAQ

Does a 404 mean the video has no thumbnail at all?

No. It usually means that one filename is missing. Mid sizes often still exist.

Is hq720 a good substitute for maxresdefault?

When it validates, yes—it is in the same high tier (~1280×720). It is not guaranteed either.

Should I retry maxresdefault later?

Yes after a new custom upload in Studio finishes processing. Otherwise, keep the validated fallback.

Can maxres exist as WebP but not JPEG?

Yes. 11tik checks WebP maxres separately under /vi_webp/. Either, both, or neither may exist.

Why do some tools still show a maxres card that breaks?

They print a template URL without loading the image. 11tik only lists files that respond as images.
