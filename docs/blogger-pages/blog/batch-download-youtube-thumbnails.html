Batch workflow (up to 50 URLs)

  1. Gather public YouTube URLs — watch, Shorts, live, embed, youtu.be, or bare 11-character IDs. One video per line. Channel-only and playlist-only URLs are not expanded.
  2. Open 11tik — go to www.11tik.com in any modern browser (desktop or phone).
  3. Turn on Bulk — click Bulk in the header (or open with ?bulk=1).
  4. Paste up to 50 URLs — one per line, then click Extract all. Processing stays client-side in your browser.
  5. Review extracted thumbnails — each successful line shows its best validated public still first.
  6. Export — download each best still, use Download all highest quality for a ZIP, and/or Export CSV for a research log. Optional JSON export is also available.

What the tool processes

Bulk mode runs the same client-side public-still check as single-URL extract: parse each video ID, build candidate thumbnail URLs, load them as images in your browser, drop failures and placeholders, rank survivors, and show the best still first. It does not download video or audio, does not call a private YouTube API, and does not store pasted links on 11tik servers.

50-URL cap

Each Bulk run accepts up to 50 public URLs (one per line). That verified limit keeps image validation responsive in the browser. For more IDs, run multiple batches of 50 or export CSV from each run and merge offline. There is no unlimited, 100+, 500+, or 1000-URL server batch.

ZIP and CSV export

ZIP: After Extract all finishes, Download all highest quality packs the best validated still for each successful video into a ZIP so you can save many thumbnails in one download. Failed or empty lines are omitted from that set.

CSV: Export CSV writes a spreadsheet-friendly log (video id, title, share URL, and validated image URL per row) for research or CMS prep. Export reflects what validated in that session—not a guaranteed maxres column for every ID. Optional JSON export covers the same session data in another format.

ZIP and CSV are features of the same homepage Extractor in Bulk mode—not a separate bulk-downloader product.

Client-side processing in the browser

Every extract happens in your session on desktop or mobile browsers. Network requests go from your browser to public i.ytimg.com (and related) hosts. Pasted URLs are not uploaded to 11tik for server-side scraping. Device-specific save quirks for a single still are covered in the iPhone / Android save guide; this page focuses on the multi-URL workflow.

Failure taxonomy

  • Parse failure: line is not a supported watch, Shorts, live, embed, youtu.be, or bare video ID (channel-only and playlist-only URLs are not expanded).
  • Video unavailable: private, removed, restricted, or processing—no public still validates. See why a thumbnail won’t appear.
  • Variant missing: video is public but maxres (or another high tier) 404s; a lower size still works. See maxres fallback.
  • Placeholder rejected: URL responded but looked like a tiny grey missing-file tile.

Invalid, private, and unavailable videos

11tik only surfaces public CDN stills. Unlisted videos without public packaging, members-only uploads, age-gated content, and deleted videos typically produce empty cards—not a smaller “secret” file. Do not expect Bulk to bypass access controls.

Channel URLs vs manually supplied watch links

Paste supported public video URLs or IDs only—one per line. Channel-only and playlist-only URLs are not expanded. For notes on working from a channel page with individual watch links, see the channel thumbnail guide.

Privacy

Pasted URLs are processed locally in your browser for extraction. Read Privacy for site analytics; Bulk does not add a separate server-side private API.

Retry guidance

After a new Studio custom thumbnail or fresh upload, wait for processing and re-run the same watch URL. Transient CDN lag sometimes clears on a second attempt; persistent empty results usually mean no public still exists for that ID.

Realistic expectations (sample-scoped sizes)

Not every public video publishes maxres. In our 300-video sample, maxres validated for 286/300 IDs (sample-scoped). Bulk returns the highest validated public file per line—not a guaranteed 1280×720 for every row. The study is evidence about sizes, not a claim about bulk throughput.
